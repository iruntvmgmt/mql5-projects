# Stage B-lite — one-factor-at-a-time ATR robustness (harness only, not yet executed)

Answers: does each strategy's Stage A canonical-settings result sit inside a
stable parameter region, or is it a narrow, lucky peak? Run across **all 8
strategies**, not just Stage A's 3 promising ones — see `DECISION_LOG.md`
D020 for the full design rationale.

**This harness has not been run yet.** Per explicit direction, Stage B
execution is gated on reviewing D021's exit-efficiency Phase 1 results
first, since exit-model choice could change which strategies are worth
spending robustness-testing time on.

## Design

- `RiskReward` fixed at `2.0` for every config — entry robustness and exit
  model are different questions; D021 owns the exit-model comparison.
- Four factors, three levels each, one factor varied at a time, everything
  else held at canonical (ATR length 14, Fast 1.0, Medium 2.0, Slow 3.5):
  - **ATR length** 10/14/20 — sets `InpFastATRLen`, `InpMedATRLen`, and
    `InpSlowATRLen` **together**; multipliers stay canonical.
  - **Fast multiplier** 0.8/1.0/1.2 — `InpFastATRMult` only.
  - **Medium multiplier** 1.6/2.0/2.4 — `InpMedATRMult` only.
  - **Slow multiplier** 3.0/3.5/4.0 — `InpSlowATRMult` only.
- The canonical level (`14`/`1.0`/`2.0`/`3.5`) is **not** regenerated here —
  it's reused from each strategy's existing Stage A RR2.0 run (or D019's
  research-mode RR2.0 run for FastBreakout, since Stage A's own FastBreakout
  RR2.0 was a 0-trade result under normal scoring, not a valid baseline).
  Reuse requires an exact match on code SHA, data interval, execution
  model, costs, symbol spec, eligibility mode, and output schema — see
  D020 for the full list; if any of those change, rerun that cell instead
  of assuming it still applies.
- FastBreakout's configs include `InpResearchMinScoreOverride=3.5` /
  `InpAcknowledgeResearchOverride=true` (D019) since it can't clear
  `InpMinScore=5.0` in isolation regardless of ATR settings — without the
  override every FastBreakout Stage B cell would be a meaningless 0-trade
  result.

64 configs total: 8 strategies × 4 factors × 2 non-canonical levels each.

## Files
- `generate_configs_stageB.sh` — regenerates all 64 `.ini` files.
- `stageB_<Strategy>_<factor>_<value>.ini` — e.g. `stageB_FastMedConfluence_atrlen_10.ini`.

## Running (once authorized)
Same harness pattern as `../StageA/run_stageA.sh`/`run_all_stageA.sh` — point
`CONFIG_DIR` at this folder instead. Remember each strategy needs its
canonical-cell result pulled from `../StageA/_master_runsummary.csv` (or
`../StageA_Research/_master_runsummary_research.csv` for FastBreakout) to
complete the 3-point-per-factor picture, since the middle/canonical point
isn't regenerated by this harness.
